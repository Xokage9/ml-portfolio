# Детекция номеров на SVHN

[← Все проекты](../../README.md) · [Ноутбук](notebook.ipynb) · [Открыть в Colab](https://colab.research.google.com/github/Xokage9/ml-portfolio/blob/main/projects/03_object_detection/notebook.ipynb)

Находить общий прямоугольник с номером дома на изображении SVHN с помощью YOLOv8n.

## Что реализовано

Чтение MATLAB HDF5 с объектными ссылками, преобразование нескольких рамок цифр в общую рамку номера, обучение детектора и отдельный анализ IoU.

## Данные

Нужен [SVHN Full Numbers](http://ufldl.stanford.edu/housenumbers/): каталоги `train/` и `test/` с PNG и `digitStruct.mat` рядом с ноутбуком. Это детекция одного номера целиком, не OCR и не классификация каждой цифры.

## Запуск

Из корня репозитория выполните:

```bash
python -m pip install -r projects/03_object_detection/requirements.txt jupyterlab
cd projects/03_object_detection
python -m jupyter lab notebook.ipynb
```

В Colab откройте ссылку выше, выполните ячейку установки и разместите исходные данные в рабочем каталоге. Для полного обучения и генерации нужен подходящий GPU; подготовка данных и часть анализа работают на CPU. Зависимости заданы диапазонами, это не lock-файл конкретного CUDA-окружения.

## Проверка качества

В подготовленной версии 20% исходного train отделяются в validation с seed=42. Официальный test не участвует в выборе эпохи. Сохранённые ниже цифры относятся к старому протоколу, где test использовался как validation; они не являются оценкой нового протокола.

## Зафиксированный результат

Сохранённый старый протокол: mAP50 ≈ 0.9202; mAP50–95 ≈ 0.5339.

Данные взяты из сохранённых выводов исходной работы. Полный запуск обновлённой версии на GPU не выполнялся. Метрики нового запуска должны сохраняться отдельно от [истории эксперимента](results/recorded_metrics.json).

## Ограничения

После изменения разбиения требуется заново обучить и оценить модель. Mean IoU дополнительно считается только для изображений с найденной рамкой; число пропусков выводится отдельно. Для общего качества нужны также recall и mAP.
