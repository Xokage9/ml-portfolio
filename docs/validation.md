# Проверка и изменения

## Что проверяет CI

Проверяются JSON и структура всех ноутбуков, синтаксис Python-ячеек, наличие описаний и зависимостей, локальные Markdown-ссылки и отсутствие сохранённых ошибок/логов. CPU-проверки используют реальные функции из ноутбуков: чанкинг, геометрию рамок, бинарные метрики масок, выделение событий и детерминированное разделение SVHN. Обучение и инференс моделей в CI не выполняются.

## Что изменено

| Проект | Изменение |
|---|---|
| Все | Добавлены постановка, данные, запуск, протокол и ограничения; убраны личные пути, execution metadata и старые выводы |
| RAG | Проверяются допустимые размер окна и перекрытие; некорректная конфигурация завершается ошибкой |
| Fuel | Повторное обучение включено по умолчанию; чужие pickle-кэши не нужны для запуска |
| SVHN | Validation выделяется из train; test используется только в итоговой оценке; уменьшен batch, добавлен CPU fallback |
| Сегментация | Убрана принудительная CUDA; согласована оценка пустых масок; среднее взвешивается по числу изображений; убран отладочный отчёт по личным фотографиям |
| Классификация | Исправлена независимая копия лучшего checkpoint; таблицы и кривые рассчитываются из текущих предсказаний и истории; парсер некорректных имён не падает с KeyError |

## Границы проверки

Полный повтор обучения на GPU в этой среде не выполнялся. Исходные сохранённые результаты вынесены в `recorded_metrics.json`; они не доказывают качество кода после изменения протокола. Отсутствующие датасеты, CUDA-совместимость и загрузка весов проверяются при полном запуске в выбранном окружении. Диапазоны зависимостей не являются полностью зафиксированным окружением.
